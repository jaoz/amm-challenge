# Cursor workspace instructions

## Keeping changes

- **Per-run change log**: Each run folder has its own `.ai.changes.md`. Log run-specific decisions and fixes there.
- **Timestamps**: Use second-level UTC timestamps in change entries, e.g. `20260218T114601Z`, not just the date.

## Tools (shared, under `Cursor/tools/`)

- **Launch / collect runs**: `Cursor/tools/optimize_theo1_local_parallel.py`
  - `--mode launch`: start workers.
  - `--mode collect --out-dir <run_folder>`: aggregate workers → `best_overall.sol` / `best_overall.json`; copy `best_overall.sol` to `best.sol` in the run folder so the run result is clearly `best.sol`.
- **Proxy / leaderboard compare**: `Cursor/tools/run_match_and_log.py` (e.g. multi-seed proxy compare, log to `Cursor/logs/`).
- **Stage A/B/C pipeline**: `Cursor/tools/run_theo1_staged_pipeline.py`
  - Native Python orchestration for Stage A workers (no shell launch mode).
  - Automatic Stage A trigger, Stage B gate, Stage C final validation.
  - Writes run PID tracking to `pids.json` in the run folder.
- **Worker scaling benchmark**: `Cursor/tools/benchmark_theo1_worker_scaling.py`
  - Measures estimated sims/min across `workers` × `sim_workers` grids.

## Folder structure

- **Runs**: `Cursor/runs/<YYYYMMDD>T<HHMMSS>Z_<strategy>_<description>/`
  - Contains: `base.sol`, `start.ps1`, `manifest.json`, `.ai.md`, `.ai.changes.md`, optional `README.md` (short description of the run).
  - After collect: `best_overall.sol`, `best_overall.json`, and `best.sol` (copy of best result).
  - Worker outputs: `workers/worker_N/` (`best.sol`, `best.json`, `progress.jsonl`, `stdout.log`, `stderr.log`).
- **Strategies**: `Cursor/strategies/champions/`, `Cursor/strategies/current/`.
- **Tools**: `Cursor/tools/` (no per-run copy).
- **Logs**: `Cursor/logs/` (e.g. proxy compare JSONL).

## Run result

After running collect, the run’s result is available as **`best.sol`** in that run folder (same content as `best_overall.sol`).

## Current operating defaults (2026-02-18)

- Stage pipeline defaults are tuned for stability and lower process pressure.
- Use **`workers=20`** and **`sim_workers=1`** for best throughput on this host.
- Keep `sim_workers=2` disabled by default unless new benchmark data shows improvement.

Benchmark reference:
- Run: `Cursor/runs/20260218T153303Z_worker_scaling_bench/benchmark_report.json`
- Ranking (estimated sims/min):
  - `workers=20, sim_workers=1` -> ~799.91 (best)
  - `workers=20, sim_workers=2` -> ~795.23
  - `workers=24, sim_workers=1` -> ~779.94
  - `workers=24, sim_workers=2` -> ~777.07

## Process control notes

- If a run is interrupted, first stop the main pipeline process, then any orphaned Python multiprocessing children.
- Use `pids.json` in the run folder as the source of truth for worker PIDs and exit codes.
- Heavy run artifact churn under `Cursor/runs/` can trigger many `git.exe` hash/object scans from Cursor Git integration.
